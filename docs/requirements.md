# 要件

## 目的

better-e7は、Androidゲーム向けの自動化をPCのOSや端末解像度から切り離し、ゲームごとの認識と操作を追加しやすくするためのデスクトップアプリです。

最初の対象はUSBまたはTCPでADB接続したAndroid端末です。PC側はmacOS / Windows / Linuxを対象にします。

## 利用者

- 自動化タスクを実行する利用者
- テンプレート画像や判定条件を調整するゲーム実装者
- Android接続 / 映像 / 認識基盤を保守する開発者

## 必須機能

### 端末接続

- ADBで接続可能な端末を一覧表示できる
- 端末を選択して接続 / 切断できる
- 端末切断を検知し、自動操作を安全に停止できる
- 複数端末を検出しても操作対象を明示的に選べる

### 映像

- アプリが管理するscrcpy-serverから映像ストリームを受信できる
- H.264をデコードし、認識とGUIプレビューへ同じフレームを渡せる
- フレームに連番 / 取得時刻 / サイズ / ピクセル形式を持たせる
- 最新フレームを優先し、処理遅延時に古いフレームを無制限に蓄積しない
- 保存画像または録画を入力にして認識処理を再現できる

### 操作

- タップ / スワイプ / Androidキーを送信できる
- ゲーム側は0.0から1.0の正規化座標を使う
- 最初はADB入力を使用でき、後からscrcpy controlへ交換できる
- 停止操作または端末切断後に入力を送信しない

### 認識

- 対象領域を指定してテンプレートマッチングできる
- 検出結果に名前 / 信頼度 / 位置を持たせる
- 検出範囲と結果をプレビューへ重ねて表示できる
- ゲーム固有コードへOpenCVの型を公開しない
- OCRやONNX推論を後から追加できる

### 自動化

- ゲーム状態を推定し、条件に合うTriggerまたはTaskを実行できる
- タスクの開始 / 停止 / 一時停止ができる
- 同時に入力する処理を1つに制限できる
- 優先度の高い復旧処理が通常タスクへ割り込める
- 実行理由 / 認識結果 / 入力内容 / エラーをログへ残せる

### GUI

- 端末選択 / 接続状態 / 開始 / 停止を1画面で操作できる
- Android映像と認識結果を表示できる
- 現在のゲーム状態 / タスク / FPS / 遅延を表示できる
- ログを表示し、調査用に保存できる
- GUIを閉じると自動操作とバックグラウンド処理を停止できる

## 品質要件

- CoreはmacOS / Windows / Linuxで同じコードを使う
- Coreはegui / ADB / scrcpy / FFmpeg / OpenCV / ONNX Runtimeへ依存しない
- 通信 / デコード / 認識の失敗をpanicで終了させず、状態とログへ返す
- scrcpy-serverの対応バージョンを固定し、アプリと一緒に管理する
- 外部から取得したゲーム画像やモデルのライセンスを記録する
- CIでformat / lint / testを3OSで確認する

## 初期リリースの完了条件

- 3OSでアプリを起動できる
- 接続したAndroid端末の映像がGUIに表示される
- 指定したテンプレートを検出し、信頼度と枠が表示される
- 検出した位置をADB経由で1回タップできる
- 停止ボタンを押すと新しい入力が送信されない
- 保存フレームを使った同じ認識結果を自動テストで再現できる

## 初期対象外

- iOS端末
- 複数端末の同時自動化
- ゲーム資産の配布基盤
- プラグインの動的ダウンロード
- GPU推論の自動選択
- scrcpy内部プロトコルの複数バージョン対応
