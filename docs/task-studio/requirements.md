実装者はこの文書、[設計](design.md)、[データ形式](schema.md)、[実装計画](implementation-plan.md)をセットで読みます。既存の動作と異なる記述は、新機能を実装した後の仕様です。

## 目的と合意した範囲

ADBで接続したAndroid端末の映像を見ながら、コードやTOMLを書かずに自動化タスクを作れるようにします。既存のeguiアプリへタスク作成画面を追加します。仮称をTask Studioとします。

利用者への確認により、次を対象とします。

- 画面へタップ位置 / スワイプ矢印 / 判定領域を配置してタスクを作れる。
- 実操作を記録し、後から順番 / 待機 / 条件を編集できる。
- ホーム / 戦闘中などの画面状態に加え、スタミナ / 周回数 / 選択対象などの情報も状態モデルで扱う。
- 端末からの情報取得には画像認識とOCRを使う。設定値は手動でも入力できる。

OCRと操作記録も今回の完成範囲です。実装を段階に分けても、これらを除いた段階で本機能の完成とはしません。

## 現状と不足しているもの

|---|---|

| `AutomationProfile`はtemplates / rulesを持つ | 状態モデル / OCR項目 / 変数 / 順序付きタスクを追加する |
| `AutomationEngine`は認識ごとにRuleを評価する | 入力完了を待って次へ進むSequenceEngineを追加する |
| `GameState`はcurrent / previous / revisionを持ち、Dispatcherが遷移を管理する | 宣言型の状態判定を同じ状態型へ接続する |

既存のRuleを並べ替えても順序付きタスクにはなりません。cooldownを待機ステップの代用にしてはいけません。

## 初回の利用手順

- 端末を選んで接続すると、映像だけが表示される。自動操作は始まらない。
- 新しいプロジェクトを作り、タスク名を入力する。
- 編集モードで映像を固定し、タップ点やスワイプ矢印を配置する。手順一覧へ対応するステップが増える。
- または記録モードで端末を操作し、送信した操作を手順一覧へ追加する。
- 画像を切り出して画面状態の条件を作る。スタミナの領域を選び、OCR結果を整数の項目へ結び付ける。
- 手順の間へ待機 / 状態待ち / 分岐 / 回数指定の繰り返しを追加する。
- 保存画面やドライランで判定と予定操作を確認し、必要なステップを1つずつ実機で試す。
- 検証して保存し、明示的に実行内容へ反映してから開始する。

## 画面構成

| 領域 | 内容と操作 |
|---|---|
| 上部 | プロジェクト名 / 保存状態 / 端末 / 接続 / 編集モード / 記録モード / 実行 / 停止 |
| 左側 | タスク / 状態 / 読み取り項目 / 変数 / 画像の一覧。作成 / 複製 / 検索 / 削除 |
| 中央の画面タブ | 端末映像、固定した画面、タップ点、矢印、認識領域、OCR領域 |
| 中央の状態タブ | 状態カードと遷移の矢印。各カードには判定条件と代表画像を表示 |
| 右側 | 選択中の点 / 手順 / 状態 / 項目の名前、値、条件、待機時間、エラー |
| 下部 | 並べ替え可能な手順一覧、実行位置、入力結果、状態変化、時刻付きログ |

1280 x 800のウィンドウで主要操作に到達できることを目標とします。狭い画面では左右のパネルを畳みます。日本語フォントの既存設定を利用し、色だけに依存せずラベル / アイコン / 線種でも状態を区別します。

内部IDやTOMLのフィールド名は詳細設定へ置きます。通常操作では表示名と説明を使います。

## モードの仕様

| モード | 画面へのマウス操作 | 端末への入力 | 自動化 |
|---|---|---|---|
| 編集 | 点 / 矢印 / 領域を作成、選択、移動 | 送らない | 停止 |
| 手動操作 | クリックとドラッグを端末操作に変換 | 明示操作だけを送る | 停止 |
| 記録 | 手動操作と同じ。送信した操作を記録する | 明示操作だけを送る | 停止 |
| ドライラン | 判定結果と予定操作を表示 | 手動操作を含めて送らない | 模擬入力で進む |
| 実行 | 実行位置と判定根拠を表示 | 実行中のタスクだけが送る | 実行 |

モード変更はドラッグを中止してから行います。編集を初期値とし、記録の開始時は対象端末を常に表示します。ドライラン中も手動入力できる現状は、新画面では変更します。

タスクの停止後も映像と状態の観察は続けます。切断は別の操作にします。アプリ全体の停止は手動操作 / 記録 / タスクの入力をすべて止めます。

## 画面上の編集

| ツール | 操作 | 作られる内容 |
|---|---|---|
| 選択 | 図形をクリック、ハンドルをドラッグ | 位置や形を変更する |
| タップ | 映像内をクリック | 固定座標のタップ点 |
| スワイプ | 始点から終点へドラッグ | 向きのある矢印と所要時間。初期値500ms |
| 長押し | 点を置いて時間を指定 | 始点と終点が同じswipe。初期値800ms |
| 画像の切り出し | 矩形をドラッグ | 原画像からPNGのテンプレートを作る |
| 判定領域 | 矩形をドラッグ | 指定テンプレートを探す領域 |
| 文字の読み取り | 矩形をドラッグ | OCRの読み取り項目と領域 |

画面内のスワイプ矢印と、状態タブの遷移矢印は別のデータです。前者は端末操作、後者は状態間の移動手順を表します。

- 図形の選択と右側フォームの選択は同期する。数値を変更しても同じ図形へ反映する。
- ドラッグ開始時に表示中のFrameを固定する。端末映像の受信は継続し、固定中であることを表示する。
- 各手順は作成時の参照画面を持てる。別画面の手順を選んだときは、その参照画面と図形を表示する。ライブへの切り替えは明示操作とする。
- ズーム / パン / ウィンドウ変更後も点や領域は同じ端末位置を指す。余白からは図形を作らない。
- 画像の外でドラッグを離した場合は作成を取り消す。微小なスワイプは確定せず、長押しへの変更を案内する。
- Escで未確定の操作を取り消す。Deleteで選択物を削除する。文字入力中はキャンバスのショートカットを発火させない。
- Undo / Redoは点の配置、ドラッグ1回、手順移動、状態変更、項目変更、参照変更を単位にする。実機へ送った入力は取り消せない。

## 実操作の記録

初期対象はTask Studio内から送信した操作です。Android本体の指操作、別に起動したscrcpyウィンドウの操作、他プロセスからのADB入力の収集は対象外です。

- クリック / 直線ドラッグ / 長押し / Home / Backを記録する。直線ドラッグの時間は実測値を使う。
- タップ判定は移動量6 egui point未満かつ500ms未満。移動量が同じ範囲で500ms以上なら長押しにする。判定値はアプリ設定にする。
- マウスを離した時点で操作を1件送る。自由曲線や押下中の連続追従は初期対象外とし、送信予定の直線矢印を表示する。
- 入力の受付 / 実行成功 / 失敗を記録に残す。成功した操作だけを通常の実行ステップとして確定する。失敗した試行は警告付きの無効ステップとして残す。
- 各操作の直前画面を保持し、入力完了後から次の操作の開始までの間隔を待機候補にする。入力中の時間を二重に待機へ加えない。
- 記録停止後に待機候補を確認できる。固定時間の待機を状態待ちへ置き換えられる。
- 記録した一連の操作は後から編集できる。停止 / 切断時には確定済みの手順を失わない。

## 状態モデルの編集

状態モデルは端末上のアプリをどう理解するかを表します。ADBのconnected / unauthorizedなどと、タスクのrunning / pausedなどは実測した運用状態として別欄に表示し、自由に書き換える対象にはしません。

| モデル | 例 | 編集できる定義 | 実行中の値 |
|---|---|---|---|
| 画面状態 | ホーム / 編成 / 戦闘 / 結果 | 名前、画像条件、優先度、安定時間、代表画像 | 判定器が更新する単一の状態 |
| 観測項目 | スタミナ、所持数、表示名、確認ダイアログの有無 | 型、画像またはOCR、領域、読取条件、有効期間 | 根拠と品質を伴う読取専用値 |
| タスク変数 | 周回数、周回上限、選択対象 | 名前、型、初期値、許容範囲、選択肢 | タスクの代入や加算で更新する値 |
| 遷移 | ホームから編成へ移動 | 出発状態、到着状態、実行するタスク | 実際に観測できた遷移を表示する |

### 画面状態と遷移

- 状態カードの追加 / 複製 / 名前変更 / 移動 / 削除を行える。
- 画像の一致 / 不一致をAND / OR / NOTで組み合わせて判定条件を作れる。画面状態の条件は画像認識に限定し、OCR項目や自分自身の状態を参照させない。
- 複数の状態が一致した場合は優先度で選ぶ。同じ最高優先度が複数残った場合は判定競合とし、並び順で黙って決めない。
- 未検出、判定途中、判定競合、映像停止を区別して表示する。未検出を特定の画面状態とみなさない。
- 状態同士を矢印で結び、移動用のタスクを選ぶ。矢印を選ぶと出発条件 / 実行手順 / 到着条件を確認できる。
- 移動タスクを実行しても、状態を到着先へ強制変更しない。画面の観測で到着を確認する。
- 遷移を定義したプロジェクトでは、未定義の移動が実際に発生しても認識した状態を表示する。想定外の遷移として記録し、実行中タスクを一時停止する。遷移が未定義のプロジェクトでは状態の観察だけを行い、この理由では一時停止しない。
- 状態の強制指定や値の上書きは、入力を送らないシミュレーションだけで使う。ライブへの切り替え時に解除する。

### 観測項目とOCR

- 型はboolean / integer / string / enumを扱う。たとえばスタミナは整数、確認ボタンの有無はboolean、選択中のステージ名は文字列にする。
- OCR領域を選ぶと、元画像 / 前処理後の画像 / 生の文字列 / 変換値 / 読取品質を並べて表示する。
- 言語は英語と日本語を初期対象とし、数字だけの読み取りも用意する。整数、区切り文字の前半または後半、文字列、選択肢への一致をフォームで設定する。
- `123 / 150`から現在値123を取り出せる。桁区切り、全角数字、余白の扱いをプレビューできる。
- 値を読む画面状態と更新間隔を設定できる。ホーム専用のスタミナ領域を戦闘中に読み続けない。
- 読取不能、低品質、型不一致、範囲外、期限切れを区別する。これらを0や空文字へ置き換えない。
- 最後に読めた値は履歴として表示できるが、現在有効な値とは区別する。現在の条件判定に期限切れの値を使わない。
- 観測値の編集は読取定義の編集を意味する。実機のスタミナなどを書き換える機能ではない。

### 変数と条件

- タスク変数は実行開始時に初期値へ戻す。前回値の暗黙の引き継ぎは行わない。
- 手順では変数への定数代入と整数の加算を扱う。任意コードや式の実行は行わない。
- 状態一致、観測項目の比較、変数の比較、画像判定を条件フォームで組み合わせる。
- 条件には実際の値、期待値、最終更新時刻、不成立の理由を表示する。
- IDは名前と分離して安定させる。参照されている状態や項目を削除するときは利用箇所を表示し、参照が解決するまで保存を確定できない。

## タスクの仕様

| 手順 | 動作 |
|---|---|
| 操作 | タップ / 検出位置へのタップ / スワイプ / 長押し / Androidキー |
| 時間待機 | 指定時間が経過するまで待つ |
| 条件待機 | 状態や値が成立するまで待つ。必ずタイムアウトを持つ |
| 分岐 | 条件が真ならthen、偽ならelse。判定不能なら有効な値を待つ |
| 繰り返し | 1〜1000回の固定回数で子手順を実行する |
| 変数操作 | 定数代入 / 整数の加算 |
| ログ | 調整用のメッセージを記録する |

手順は一覧からドラッグで並べ替えられます。分岐と繰り返しは折り畳める子手順として表示し、入れ子の深さは8までに制限します。自由なgoto、無制限ループ、並列タスク、任意スクリプトは初期対象外です。

タスクは開始条件 / 最大実行時間 / 期待する終了状態を持てます。入力成功はADBコマンドの成功であり、目的の画面へ移動できたこととは区別します。画面変化は次の条件待機または終了条件で確認します。

## 試行と実行

- 構造検証、保存画面での判定、ドライラン、選択ステップの実機試行、全体実行を用意する。
- 保存前の内容を試す場合も、試行開始時点の内容を固定する。実行中の編集は実行内容へ混ざらない。
- 選択ステップの試行は前の手順を実行しない。必要な画面 / 変数を表示し、開始条件を満たさなければ拒否する。
- 一時停止は実行中の入力の結果を待ってから確定する。再開時は停止期間を待機時間へ含めず、画面と観測値を再評価する。
- 停止は未送信入力を捨て、新しい入力を受け付けない。送信済みのタップやスワイプを取り消せるとは表示しない。
- 切断後に再接続しても自動では再開しない。対象端末が変わった場合も古い試行を継続しない。
- ドライランは端末側の画面変化を作らない。条件待機が進まない場合に理由を表示する。保存画面列または明示した模擬状態を使って続きを検証できる。

## 保存と復旧

プロジェクトは実行用TOML、編集用TOML、画像からなるフォルダです。フォルダをコピーして別PCへ持ち運べます。実行定義と編集情報の形式は[データ形式](schema.md)で定めます。

- 未保存の変更を表示し、別プロジェクトへの切り替えと終了時に保存 / 破棄 / 取り消しを選べる。
- 下書きを自動保存し、異常終了後に復元できる。下書きは実行用ファイルを上書きしない。
- 画像不足、参照不正、保存先へ書けない場合は以前の正常な保存を維持する。
- 保存しても実行中の定義へ自動反映しない。停止中に明示的に反映する。
- 既存のRule用TOMLを引き続き読み込める。状態や順序付きタスクへの自動変換は行わない。

## 品質目標

以下は実測結果ではなく実装後の受入目標です。計測端末 / OS / 映像サイズを結果と一緒に記録します。

| 対象 | 目標 |
|---|---|
| 編集操作 | 1080p映像、100手順、20状態で入力から表示までp95が100ms以内 |
| 画面更新 | OCR中も操作可能で、30fpsの入力に対してプレビュー30fpsを目標にする |
| 画像判定 | 完了した認識からモデル表示までp95が100ms以内 |
| OCR | 可視の読み取り項目は初期値500ms間隔。端末ごとの負荷に応じて調整可能 |
| 停止 | 停止受付をGUIへ100ms以内に表示。受付後は新しい端末入力を開始しない |
| メモリ | 最新映像と最新認識を上書きし、画像参照とUndoのメモリ上限を設ける |
| 再現性 | 時刻と認識結果と入力結果を固定すると、状態遷移と手順実行が一致する |

通常CIは既存どおりUbuntuを使います。macOS / Windowsは手動workflowと実機確認を使い、通常CIへmacOS runnerを追加しません。
