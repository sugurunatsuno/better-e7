# タスク作成GUIの実装計画と受入条件

状態: 実装前の作業指示書。今回のコミットは文書のみで、ここにある実装項目は未着手です。

## 実装を始める前に

[要件と操作仕様](requirements.md)、[設計](design.md)、[データ形式](schema.md)、[ADR](../decisions/visual-task-studio.md)を読んでから着手します。実装開始時のdevelopとの差分を確認し、この文書の調査基準以降に同じ機能が追加されていないか確かめます。

今回の目的は、画像とOCRで端末の状態を理解し、画面への配置と実操作の記録の両方でタスクを作れることです。ルール編集画面の見た目を変えただけでは完了しません。

## 実装順と依存関係

| 作業 | 主な変更先 | 依存する作業 | 完了時に確認できるもの |
|---|---|---|---|
| 接続と入力の分離 | runtime / app | なし | 映像へ接続しても自動入力されず、停止後も映像を見られる |
| 座標と観測の基盤 | core / adb / runtime | 接続と入力の分離 | 縮小映像とADBの座標が一致し、古いFrameと別端末の結果を拒否できる |
| v2文書と保存 | automation / runtime | なし | 新旧TOML、asset、編集情報、下書きを失わず保存できる |
| キャンバス編集 | app | 座標と観測の基盤 / v2文書と保存 | 点と矢印とROIを置き、フォームと同期して保存できる |
| 状態モデル編集 | automation / game-api / app | キャンバス編集 | 状態カードと判定条件を作り、状態と根拠を確認できる |
| OCRと観測項目 | ocr / vision / runtime / app | 状態モデル編集 | スタミナなどを型付きで読み、失敗と期限切れを区別できる |
| 順序付きタスク | automation / runtime / app | 状態モデル編集 / 入力完了通知 | 待機 / 分岐 / 繰り返しを含む手順を1入力ずつ実行できる |
| 実操作の記録 | runtime / app | キャンバス編集 / 順序付きタスク | 送信した操作を記録し、同じ手順形式で編集できる |
| 統合と仕上げ | app / runtime / docs | 上記すべて | 作成から実行と修正までを一連の操作で完了できる |

小さな機能branchまたはdevelop上の変更に分け、各段階で通常CIを通します。各変更には該当するテストと文書を含めます。依存順のない作業もありますが、この指示書では担当者や並列実行を固定しません。

## 接続と入力の分離

- `RuntimeCommand::StartAutomation`の接続処理とRule開始処理を分ける。
- `StopAutomation`による入力停止と映像切断を分ける。アプリ終了時は従来どおり全workerを終了する。
- runtimeへ入力所有者と実行状態を追加し、手動 / 記録 / Rule / Task / ドライランの同時入力を防ぐ。
- session ID / run ID / operation IDを入力と完了通知へ通す。InputQueuedを成功扱いにしない。
- 期限付きADB runnerと停止の同期点を作り、入力workerを待つ処理でGUIや停止受付を塞がない。
- 既存の手動タップ、Home / Back、Rule実行の回帰を確認する。

完了条件は、接続だけではInputControllerを1回も呼ばず、タスク停止後は接続を保ったまま新しい自動入力が0件になることです。

## 座標と観測の基盤

- PreviewTransformをGUIの見た目から分離し、ズーム / パン / 縦横比 / 余白の逆変換を単体テストにする。
- DisplayGeometryProviderを追加し、実際の入力サイズを取得する。対象Android版の出力fixtureを残す。
- `queue_input`の映像サイズへの依存を置き換える。geometry revisionを入力直前にも検証する。
- 最新Frameと認識結果を対応付ける。固定画面用のArc参照をGUIに保持する。
- 静止画面での観測更新と入力後の確認用に、期限付きの補助スクリーンショット取得を追加する。
- 回転 / 切断 / 再接続 / geometry取得失敗を再現し、編集は維持しつつ誤った位置へ送らないことを確認する。

ここで縮小映像の入力位置が一致しなければ、実操作の記録や実機試行を公開する段階へ進みません。

## v2文書と保存

- v1とv2のloaderを分け、既存の構造体リテラルとテストへ不用意な必須フィールドを追加しない。
- stable ID、参照検証、型付き値、Predicate、StepDefinitionを実装する。
- 保存時は実行用TOMLを最後に切り替える。asset保存、編集情報保存、最終置換の各失敗を注入する。
- 保存結果のrevision照合、下書き復元、外部変更検知、別名保存を実装する。
- v1の読込と保存、v2への明示移行、未知versionの拒否をテストする。

完了条件は、文書のv2例が新loaderで読み書きでき、途中失敗後も以前の正常なプロジェクトを読み込めることです。

## キャンバスと状態モデル

- `show_preview`を映像表示とpointer処理に分け、編集モードの操作をADB送信へ流さない。
- タップ点、スワイプ矢印、長押し、テンプレート切り出し、ROI、OCR領域のツールを作る。
- 図形と手順一覧と詳細フォームを同じDraftへ接続する。Undo / Redoはドラッグ1回を1変更にする。
- 状態カードと遷移線を作り、判定条件と利用タスクを編集する。
- StateEstimatorの候補、安定化、競合、unknown、根拠画像を表示する。
- `GameState::apply_observed_state`を既存transition実装へ接続し、既存Dispatcherのテストを維持する。
- 変数定義、初期値、範囲、現在値を編集画面と実行画面で区別する。

完了条件は、実機または保存画面から状態を作り、画面が変わるとcurrent / previous / revisionと判定理由を確認できることです。

## OCRの評価と実装

OCR adapterの本実装前に、実際に利用するゲームのスタミナ / 所持数 / 日本語名称を代表する画像を用意します。利用者の画像が未提供なら生成fixtureで機能を作れますが、実画像での精度確認を済ませたとは扱いません。

- 正例だけでなく、暗転 / アニメーション / 隠れた領域 / 読めない画像を含む評価セットを作る。
- 各項目の実画像を最低30枚用意し、期待値と読取不能の正解ラベルを付ける。共有できない画像は通常repoへコミットしない。
- Tesseractと学習データの版、前処理、言語、品質閾値を固定し、完全一致率と誤受理率を記録する。
- 暫定ゲートは読取可能画像の95%以上で完全一致、読取不能画像を有効値として採用するケースが評価セット内で0件とする。値を間違えて有効とするケースを別に報告する。
- ゲートを満たさない項目はROIと前処理を調整する。それでも不足する場合はOcrBackendの代替を比較し、ADRを更新する。読めない値の推測で通過させない。
- `better-e7-ocr`へprocessの起動 / TSV parse / timeout / killと回収を実装する。入力画像の一時ファイルは処理後に削除する。
- OCR未導入時は保存と編集を使えるままにし、必要な言語データと設定箇所を表示する。
- 数字 / `123 / 150` / 全角数字 / 桁区切り / enum / 範囲外 / 低品質をfixtureで確認する。

実画像の精度や3OSの依存導入は現時点で未検証です。これは実装時の検証課題であり、数値読取やOCRを後回しの対象へ変更するものではありません。

## 順序付きタスクと記録

- 仮想時計と模擬入力結果を使うSequenceEngineを作る。
- ステップごとの開始、入力待ち、完了、失敗、タイムアウト、pause / resumeを実装する。
- 状態と観測値による待機、三値の分岐、有限repeat、変数代入と加算を追加する。
- Task開始条件と終了条件を評価し、遷移の矢印から対応タスクを実行できるようにする。
- single step、dry-run、保存画像列の実行を同じengineへ接続する。
- Recorderを入力の受付と結果へ接続する。記録中の直前Frame、待機候補、失敗した操作を保持する。
- 記録後に固定待機を状態待ちへ変更し、図形や所要時間を調整して再実行できるようにする。

## 受入テスト

| 観点 | 操作またはfixture | 合格条件 |
|---|---|---|
| 入力の分離 | 接続し、点 / 矢印 / 領域を100回作る | InputController呼び出しが0件 |
| 手動と記録 | タップ、ドラッグ、長押し、Backを送る | 操作ごとに1入力、成功ごとに1手順。失敗は有効な手順にしない |
| 座標 | 1920 x 1080の入力先を960 x 540で表示、DPIとズームを変更 | 中央と四隅が既存round規則で一致し、誤差は最大1入力pixel |
| 領域 | 四辺の端、逆向きドラッグ、余白、面積0 | 原画像を正しく切り出し、不正な領域を拒否 |
| 回転 | 90度と180度の変更を入力前に通知 | 未送信入力が失効し、古いgeometryの入力が0件 |
| 静止画面 | streamに更新がないが端末は接続中 | 切断扱いにせず、条件確認に必要な補助画像を取得 |
| 状態推定 | 候補が交互に一致、同点、無一致、安定した一致 | 短い揺れで確定せず、競合理由が見え、確定時だけGameState revisionが変わる |
| OCR | 正常整数、低品質、範囲外、期限切れ、別画面から遅着した結果 | 正常値だけが有効。失敗が0にならず、古い値で入力しない |
| 状態と値の同期 | state変化後に古いOCR結果が完了 | 該当値を採用せず、参照している条件はUnknown |
| 三値論理 | UnknownのNOT、AND、OR、if | UnknownをFalseへ変換せず、意図しないelseへ進まない |
| 入力完了 | 成功通知の遅延、同じ通知の重複、別runの通知 | 正しい通知1回でだけ次へ進み、入力が重複しない |
| 時間 | delay、wait_untilの期限、入力中pause、再開 | 待機と入力時間を二重計上せず、pause後に完了操作を再送しない |
| 分岐と反復 | 3回repeat、内部if、変数加算 | 指定した分岐と回数だけ実行し、overflowを拒否 |
| 停止 | queue満杯、process起動直前、ADB応答なし | 停止受付後のprocess起動が0件。起動済みは結果不明を含めて回収 |
| 実行の排他 | タスク中に手動入力、ドライラン中に旧SubmitInput | runtimeが拒否し、端末へ届かない |
| 遷移 | 定義済み移動と想定外移動 | 観測した状態を表示し、想定外の移動でタスクが停止または一時停止 |
| 保存 | 画像保存失敗、編集情報保存失敗、最終置換失敗 | 以前の実行用TOMLとassetが有効なまま |
| 保存競合 | 保存中に編集し、外部からもファイルを更新 | 新しい編集を保存済みにせず、外部変更を黙って上書きしない |
| 互換性 | 既存automation.example.tomlと旧JSONL | 従来のRule動作と履歴の読取を維持 |
| オフライン | 固定した画像列 / 時刻 / OCR結果 / 入力結果 | 同じ状態とstep順になり、EOF待機を成功にしない |

テストは公開された振る舞いと失敗時の境界を確認します。eguiの内部メソッド呼び出し順を写したテストや、見た目だけの大量snapshotは追加しません。

## 実機で行う一連の確認

- USB接続で映像を表示し、ホーム状態のテンプレートとスタミナのOCR項目を作る。
- タップ点とスワイプ矢印を配置し、時間待機と状態待機を追加して保存する。
- 記録モードでも同じ操作を行い、記録結果を編集し、生成した待機を状態待ちへ変更する。
- スタミナを条件にした分岐、周回数を使う変数操作、有限の繰り返しを設定する。
- ドライラン、single step、全体実行の順に確認する。停止とUSB切断で追加入力が止まることを確認する。
- アプリを再起動し、プロジェクトの状態図、手順、参照画像を復元する。
- 別directoryへプロジェクトをコピーして同じ内容を読み込む。
- macOS / Windows / Linuxで起動、ドラッグ、DPI、保存、ADB、OCRを確認する。Android実機のOS版と解像度も記録する。

## 完成の判断

以下をすべて満たして機能を完成とします。

- [ ] 画面への配置と実操作の記録の両方で、同じタスク形式を作れる。
- [ ] 画面状態、遷移、OCRの観測項目、タスク変数をGUIで編集できる。
- [ ] 入力完了、状態待ち、三値条件、停止、再接続を仕様どおり扱える。
- [ ] 既存Ruleの読込と実行を維持し、v1からの移行で情報を失わない。
- [ ] 通常CIのformat / clippy / testに合格する。
- [ ] 実画像のOCR評価と3OSの手動確認を記録する。
- [ ] README / configuration / automation-profiles / architecture / testing / roadmapを実装後の内容へ更新する。

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
```

## 実装着手時に確かめる項目

| 項目 | 現時点の方針 | 確認する段階 |
|---|---|---|
| 対象Android版と機種 | メインdisplay、向きを固定して開始 | DisplayGeometryProviderの実機評価 |
| OCRの実画像 | スタミナ / 所持数 / 日本語名称が対象 | OCRの評価ゲート |
| OCRの配布 | 最初は外部Tesseractと学習データを設定。自動downloadは行わない | OCR導入と配布設計 |
| 任意方向へ曲がるドラッグ | 初期は始点から終点への直線 | 必要性が分かった段階でscrcpy controlと合わせて別設計 |
| Android本体や別scrcpyの操作記録 | 初期対象外 | 別の入力監視機能として検討 |
| 複数端末の同時実行 | 初期対象外 | 現行の単一端末方針を維持 |

これらを確認するまでGUI全体の実装を止める必要はありません。mockと保存画像で作業を進め、実機や実画像の検証結果を推測で埋めないことを条件にします。
